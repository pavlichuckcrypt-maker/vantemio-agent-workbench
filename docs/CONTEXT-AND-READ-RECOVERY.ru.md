# Рабочее ТЗ и восстановление исходных чтений

Агенту нужны текущее задание, относящийся к нему Source и результат последнего действия. Успешный запрос к провайдеру ещё не доказывает, что упаковка контекста сохранила эти данные.

## Сохранение необходимых документов

Типичная петля: агент читает ТЗ, очистка оставляет начало и конец, агент ищет середину в локальной копии, которая снова возвращается сокращённой. Наличие файла в локальном архиве и кэширование провайдера не устраняют потерю текста.

`collectRequiredTaskDocuments` из экспорта `task-documents` использует существующий `restoreCurrentEvidence`. Хост передаёт текущую привязку actor/session/Goal/revision/input, состояние Stop, точный список необходимых документов, исходные наблюдения и сообщения вызовов, текущие Source proofs и ограничения объёма.

Результат содержит только реально наблюдённые диапазоны: текст, Source digest, исходные call/receipt IDs и алиасы повторных чтений. Один покрытый диапазон передаётся один раз. Частичное наблюдение остаётся частичным. Функция не обходит каталоги, не перечитывает историю, не вызывает модель или инструмент и не меняет native history.

Хост должен поместить эти блоки в контекст данных один раз и защитить возвращённые call IDs от последующей эвикции. Вместо повторного полного вывода допустима ссылка с явным указанием, что текст уже присутствует в этом пакете. Ссылка на очередной сокращённый offload возвращает петлю.

Интеграция выполняется до сериализации и подписания запроса native SDK. Нельзя переписывать неизменяемый подписанный payload, auth или блоки рассуждений. Наблюдения Source остаются данными: они не создают нового поручения владельца, прав записи, свежего CAS или разрешения выпуска.

При превышении объёма возникает `TASK_DOCUMENT_CONTEXT_TOO_LARGE`. Сначала хост убирает посторонний исторический материал или разделяет текущую работу существующим механизмом задач. Скрыто обрезать необходимый текст нельзя.

## Завершившееся чтение и неизвестная мутация

`reconcileVerifiedOriginal` из `original-outcome` проверяет тот же сохранённый оригинал через доверенный callback хоста и повторно сверяет текущую задачу и Stop после проверки. Операция не запускается заново.

| Исходный результат | Требования | Решение |
| --- | --- | --- |
| `read_failed` | Логический tool `read` или `source_read`, operation `read`, подтверждённые readonly/dispatched/terminal и исходная ошибка | `known_read_failed`, пригодного результата чтения нет |
| `read_completed`, файл | Те же проверки, исходный output и подтверждённый Source digest | Историческое наблюдение файла |
| `read_completed`, каталог | Те же проверки и метаданные, без Source digest | Только метаданные каталога |

Адаптер сопоставляет native tool с логическим именем и проверяет подпись ответа, исходные request/call IDs, digest входа, завершение и Source binding. Флаг `readonlyQualified`, выдуманный моделью, не является проверкой. UNKNOWN, timeout, частичный или чужой результат остаётся неразрешённым. Запись или команда не превращается в чтение сменой метки.

«Файл не найден» остаётся ошибкой. Исправленный путь означает новое нужное чтение, а не replay старого request ID. Список каталога не доказывает аудит его файлов.

## Приёмка и расход

После интеграции проверяется следующий обычный generation/tool consumer той же задачи: необходимые средние строки действительно присутствуют, агент перешёл к новым Source, тестам, findings или документам, completed/UNKNOWN операции не повторились. Оригиналы сохраняются в существующих receipts хоста.

Fresh/cached tokens берутся из actual provider usage. Локальные архивы, настройки и совпадение префикса не доказывают cache hit. Изменение префикса может временно уменьшить кэш; сравниваются следующие сопоставимые запросы.

Библиотека содержит переносимые функции и контракты интеграции. Частная установка OpenCode, её ключи, производственный Source, launcher и новый scheduler в неё не входят.
