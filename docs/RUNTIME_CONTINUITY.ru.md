# Непрерывность работы — версия 0.6.0

Переносимые модули общей инфраструктуры: исходные результаты инструментов, продолжение после отказа до отправки, защита Stop/Goal, ограниченный кэш доказательств, представление большого чтения и сигналы продвижения. Это библиотека для существующего хоста; она сама не подключает OpenCode, не хранит ключи и не отправляет запросы. Полный технический контракт: [RUNTIME_CONTINUITY.md](RUNTIME_CONTINUITY.md).

- `original-outcome`: доверенный адаптер хоста проверяет подпись и SAME original request/call/tool/input/Goal/task. Состояние перепроверяется после ожидания. Код0 — завершённое выполнение, ненулевой — известная ошибка; readonly timeout — отсутствие пригодного результата, а не PASS. UNKNOWN не превращается в завершение. Повтор операции и освобождение claims запрещены.
- `proof-cache`: LRU ограничен фактически сохранёнными JSON-байтами и числом записей. Копии защищают учёт от изменения вызывающим кодом. Вытеснение требует повторной проверки исходной квитанции, а не повторного исполнения.
- `control-state`: текущие Goal/revision/input/Stop/permissions/live tools проверяются перед продолжением. Принятый ввод не пересылается. Нативный SDK сохраняет выбор провайдера, модели и рассуждений. Синхронный CAS файла рассчитан на одного эксклюзивного писателя хоста; для нескольких процессов нужен существующий транзакционный механизм. Записываются intent и неизменяемый accepted/UNKNOWN receipt. Новый Stop не перезаписывается.
- `maintenance-hold`: старый релиз не может снять более позднюю паузу обслуживания. Проверяются operation/manifest/actual PID/actor/root/Goal. Сам предикат состояние не меняет.
- `source-presentation`: сокращённое представление содержит исходный hash/call, пропущенные строки и координаты архива. Хост заранее сохраняет и проверяет оригинал. Для изменения/приёмки необходимо прочитать недостающие строки. Обязательные PROJECT/AGENTS/SKILL/Goal/Source и неизвестные результаты не сокращаются этим механизмом.
- `runtime-progress`: одинаковое чтение с новым callID/limit не становится новым доказательством. Новые Source/ranges/task учитываются. Чтение не запрещается произвольной квотой. Сигнал продвижения не доказывает внедрение или успешный тест и не должен автоматически останавливать агента.

Настраивать надо общий путь хоста, затем проверять обычный следующий assistant/tool каждого чата. Локальный архив не означает provider cache. Максимум необходимых новых токенов — запас, а не цель заполнения. Приватные адаптеры, ключи, история и продуктовые исходники в публичный пакет не входят. Offline тесты и установка пакета не заменяют приёмку работающего хоста.

`active-read-context` сохраняет уже проверенные чтения активных рабочих файлов для следующего действия: прошлое исключение из пакета больше не считается доказательством, что код сейчас не нужен. Сверяются input/latest action, tool/path и hashes оригинала. Подключать до исключения исторических чтений; это не восстановление всего архива и не увеличение лимита.
