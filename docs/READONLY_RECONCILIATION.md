# Readonly original reconciliation

`readonly-reconciliation` separates model observation from permission to execute changes. It does not install a host hook, settle an original operation or resume a chat by itself.

If an original effect is unknown, a host may project request admission only after it verifies the same actor, session, Goal revision and native input, an installed outermost execution fence, locally executed function tools and an exact-original observer. The actual execution fence must check again before changes and retain unresolved originals beyond a bounded history page. Readonly observation errors must remain failed observations rather than fabricated unknown writes.

`projectReadonlyReconciliation(task, gate)` leaves Stop, permissions, live tools and unknown admissions guarded. A qualified projection explicitly retains uncertainty and grants no replay or release approval. The default request adapter remains strict. Tool schemas, native provider/model/variant and authentication remain owned by the host SDK.

A host must authenticate the stored original result, never reissue its command. A signed failure stays a failure. Archive results are not fresh Source, and a successful process observation does not prove completion of descendants. Predispatch refusal must have a content-addressed, actor/call/input/argument-bound no-execution proof so it cannot become another unknown write.

Only pure policy and tests are distributed here. Transport, native callback, execution-fence and ordinary-consumer integration belong to the embedding host and need separate verification. A policy test alone is not runtime acceptance.
