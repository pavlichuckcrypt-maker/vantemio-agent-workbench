# Operating an autonomous coding-agent fleet

Assign one infrastructure maintainer in the existing host. The maintainer owns shared hooks, context preparation, request budgets, recovery guards, skills-on-demand, measured usage and the public toolkit. It does not replace product developers or issue instructions for every healthy step.

## Change and recovery procedure

1. Read the current actor registry, full task/Goal/revision, native model selection, Stop state and original outcomes. A stale title or old process ID is insufficient.
2. Reproduce the specific defect and change the shared cause. Preserve current input, original call IDs, completed work, live tools and unknown effects.
3. Run relevant positive, negative and regression checks. Provider quota, authentication and unsupported-model failures require correction; technical retries remain bounded.
4. Load through the existing host lifecycle at a verified idle boundary. Record every maintenance-owned interruption. New user or peer inputs supersede a snapshot: reconcile their exact identity and content before proceeding.
5. Restore the exact normal pacing. Resume only qualified unfinished model steps; never replay tools or resend an accepted/unknown delivery. Preserve genuine Stop.
6. Confirm a completed ordinary assistant generation and its next normal tool/caller. A launch receipt, accepted continuation, helper PASS or busy indicator is not acceptance.

## Efficient context

Keep a stable necessary prefix and task-bound Source/results identified by original call, receipt, SHA and range. Load skills only when needed. Keep stale results in local storage rather than injecting an archive into each request. Source correctness and task continuity take priority over a cache percentage. Only provider-reported usage proves a cache hit; missing usage remains unknown.

## Public updates

Review the exact diff, run the tests, release allowlist/sensitive-data scan and installed-package smoke consumer. Publish only reusable policy code, sanitized examples and RU/EN documentation. Credentials, chat history, native identities, private transports, host paths and product Source stay outside the public repository. Configuration examples require a qualified host integration; this toolkit does not dispatch models or provide a hosted OpenCode service.
