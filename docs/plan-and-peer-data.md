# Bounded plan and peer data

Large developer plans and old peer diagnostics can fill a request even when the code needed for the current action is small. Keep them in the existing host archive and provide a useful verified display. This is local retention; it does not imply provider cache usage.

`projectPeerResumeSnapshots` from `vantemio-agentic-backend/peer-observation` projects only explicitly non-authoritative row snapshots. Known unavailable-host observations remain byte-for-byte unchanged as data. Other malformed or authority-bearing records prevent projection. Archive the complete original before using a changed display. Stop, identities and claims remain observations; this helper grants no execution or Source authority.

`pageCurrentPlanReadResult` from `vantemio-agentic-backend/plan-observation` handles a native read of an explicitly declared local PLAN.md or CURRENT_WORK.md. The host must bind the exact current workspace/file, call ID, result SHA and already supplied excerpt, verify that the complete current Goal/task and unfinished native TODO are inline, and exclude every explicitly required Source/document pin. Apply it when the current working set needs reduction.

The display retains an exact head and tail, the original returned-row bounds and native footer, an explicit missing character window and a complete SHA-bound archive reference. Native line-continuation payloads remain in that full archive. Current project specifications and Station Source are not eligible. The original native result and history are unchanged. A page does not prove full-file review, current file bytes or fresh CAS authority.

Archive callbacks must store the entire supplied original and return its exact SHA and usable file path. A mismatched archive is rejected. The host must recheck its ordinary Stop/current-input/Goal/permissions/UNKNOWN guards before continuing; these utilities neither invoke a model nor replay a producer.
