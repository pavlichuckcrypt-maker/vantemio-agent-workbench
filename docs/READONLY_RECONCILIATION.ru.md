# Сверка исходной операции в режиме чтения

`readonly-reconciliation` отделяет допуск модели к наблюдению от права выполнять изменения. Модуль сам не ставит host hook, не закрывает исходную операцию и не возобновляет чат.

При неизвестном эффекте host может допустить запрос только после сверки actor/session/Goal/revision/native input, установленного внешнего предохранителя исполнения, локальных function tools и наблюдателя точного оригинала. Предохранитель проверяется снова перед изменением; невыясненные оригиналы сохраняются и за пределами страницы истории. Ошибка чтения остаётся неудачным наблюдением и не подменяется неизвестной записью.

`projectReadonlyReconciliation(task, gate)` сохраняет Stop, разрешения, живые инструменты и неизвестный допуск. Квалифицированная проекция явно сохраняет UNKNOWN и не даёт права повтора или release. Обычный request adapter остаётся строгим. Выбор provider/model/variant/auth принадлежит native SDK.

Host проверяет сохранённый подписанный результат, не отправляя команду снова. Подписанная ошибка остаётся ошибкой. Архив не является свежим Source; завершение процесса не подтверждает завершение потомков. Отказ до исполнения требует content-addressed доказательства, связанного с actor/call/input/аргументами, чтобы не стать новой неизвестной записью.

Пакет содержит только переносимую политику и тесты. Transport, native callback, предохранитель исполнения и следующий обычный consumer проверяются отдельно в host. PASS политики не равен runtime-приёмке.
