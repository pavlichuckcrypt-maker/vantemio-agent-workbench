# Корневой контекст native-агента — версия0.6.1

Необязательный модуль `./harness-root-context` сохраняет корневые инструкции на проверенной границе Harness/pi-ai. В некоторых сочетаниях SDK корневой текст записывается в старое поле `systemPrompt`, тогда как конечный сериализатор ожидает первое системное сообщение в `messages`. Остальные сообщения могут передаваться успешно, а корневой контракт — исчезать.

Нормализатор возвращает новое неизменяемое представление запроса. Исходные сообщения и история сохраняются, провайдер/модель/рассуждение/выходной бюджет/сигнал/авторизация остаются нативными. Текст пользователя или инструмента не повышается до корневых инструкций. Уже подготовленные вызовы завершаются со своим снимком; исправление применяется к последующим подготовкам. Новые совместимые регистрации подхватываются через существующее событие SDK, без нового агента, сервера, очереди или цикла повторов.

## Проверка и подключение

Полный контракт и YAML: [HARNESS_ROOT_CONTEXT.md](HARNESS_ROOT_CONTEXT.md). На фактическом хосте задайте `HARNESS_TEST_MODULE_ROOT` точным путём установленного SDK, затем выполните:

```sh
npm run test:native-root
node scripts/qualify-harness-root.mjs '<абсолютный SDK node_modules>' '<абсолютный каталог состояния хоста>'
```

Синтаксис переменных окружения зависит от оболочки. Нативная квалификация проверена на Node24 и использует уже установленный SDK. Тесты доходят до конечного payload Responses, Chat Completions и Anthropic, но останавливаются до HTTP; реальный ключ не нужен, обращения к провайдеру запрещены. Проверяются воспроизведение потери корневого текста, его сохранение ровно один раз, пары инструментов, неизменяемость запроса, ручной выбор модели и сохранность текущего подготовленного вызова.

Квалификатор печатает пути и хеши модуля/методов, не меняет настройки и не читает ключи. После успешных тестов подключите модуль один раз существующим plugin manager. В patch-профиле новая запись добавляется через `insert`: простой `id` выбирает уже существующую запись. Сохраняйте свежий профиль и чужие изменения через CAS; не выгружайте работающий модельный адаптер ради проверки.

Приёмка: фактически активный модуль, `ROOT_CONTEXT_COMPAT_READY.json`, реальный процесс и следующий обычный assistant/tool того же чата. Диагностика `root-contract-forwarding/<хеш сессии>.json` содержит счётчики и хеш корневого текста до dispatch; сама по себе она не доказывает успешного ответа. После изменения SDK нужна новая квалификация. Модуль не создаёт провайдеров и не подменяет нативный выбор модели/авторизации.

## Директива области работы

`qualifyOwnerScopeClause` из `./scope-policy` проверяет хеш конкретной директивы, выделенной доверенным кодом хоста. Изменение строки о кэше или другой части документа не отключает прежнюю область работы. Отсутствующая, неоднозначная, изменённая или слишком большая директива не проходит проверку. Регистр путей сохраняется; нормализуется только пробельное оформление. Проверка не выдаёт полномочий и не заменяет actor/Goal/Source-привязку хоста.

Нужные данные остаются в рабочем наборе либо доступны по точным локальным ссылкам. Локальный архив не равен provider cache. Пример допускает до50k необходимых новых токенов, до70k кэша и до80k суммарно при целевом свежем входе15k. Это допустимые пределы при подтверждённой необходимости и usage, а не цель заполнения и не обещание процента кэширования. Полное сжатие истории — отдельный механизм хоста.


## Текущие документы и scoped lifecycle

Дополнительный `./current-task-artifacts` формирует текущие native developer-data views по CURRENT_TASK_ARTIFACTS.json: schema1, точный taskSHA256 файла TECHNICAL_TASK.md, goalID и до8 объявленных файлов. История — mode:"reference" по необходимости; inline документы и их общий набор ограничены32KiB. Невалидная карта не является квалифицированным источником задачи.

Root plugin восстанавливает потерянные между Session и frozen adapter input документы только после проверки same-session native provenance, live Goal, task metadata и фактических байтов/хешей. User/tool текст не повышается до developer-инструкций; исходный frozen request и история сохраняются. Для этого optional root config указывает currentArtifactsModule на установленный src/current-task-artifacts.mjs и currentArtifactsModuleSHA256 на хеш этого файла; producer использует те же moduleRoot/stateRoot и собственный workspace Session. Без активной квалифицированной Goal восстановление не объявляется успешным. PLAN располагается после стабильной карты.

Выгрузка использует native Cordis ctx.effect; она освобождает только собственные wrappers, сохраняет чужие последующие замены и уже подготовленные calls. Отсутствующий scoped lifecycle отклоняется до изменения adapter. Ready/хеши/тесты не заменяют следующий обычный assistant/tool consumer. Локальное сохранение не доказывает provider cache hit.
