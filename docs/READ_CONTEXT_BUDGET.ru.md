# Служебный контекст и подтверждённые текстовые чтения

Ограничение кода не охватывает автоматически описания SDK, пути каталога навыков и последнее чтение документа. Измеряйте весь собранный пакет с фактической калибровкой провайдера. Предыдущий cache hit не увеличивает безопасный потолок при промахе кэша.

Порядок интеграции в существующий host:

1. Сохранить текущие owner instructions, полную Goal/task и явно обязательный Source. Не менять native provider/model/variant/auth и права исполнения.
2. Сначала вызвать `presentSkillCatalogOnDemand`: пути разрешаются native skill tool, неизвестные поля и повреждённые каталоги сохраняются без догадок.
3. Затем применить `compactServiceDescriptions` по общей таблице проверенных SHA описаний SDK. Сокращение подсказок схем требует отдельного точного SHA схемы. Полные оригиналы остаются в архиве; validation keywords, defaults, enum, required и native исполнение не меняются. Пользовательские и неизвестные описания не переписываются.
4. До отправки сохранить и проверить архив. Перед применением навыка загрузить его полные официальные инструкции через native skill tool.
5. Для всех завершённых текстовых READ использовать одну политику доказательств и бюджета, включая документацию. `presentVerifiedTextRead` сохраняет точный оригинал, SHA, call ID, исходные номера и явно отсутствующие строки. Расширение файла не даёт исключения из бюджета. Бинарный, неподтверждённый или ошибочный результат не становится подтверждённым Source.
6. Повторно измерить окончательный пакет и применить неизменный hard admission. Host сохраняет обязательные требования и решает, какие наблюдения допускают постраничное представление. Неполный preview не означает полного аудита, свежего Source/CAS, приёмки выпуска или разрешения повторить операцию.

API и пример импорта приведены в [английской версии](READ_CONTEXT_BUDGET.md). Whole-body SHA архива относится к квитанции запроса. Для устойчивой ссылки в prompt храните отдельный content-addressed архив только метаданных; не добавляйте timestamps и новые body SHA в начало повторно используемого контекста. Локальный архив и одинаковый prefix не доказывают кэш провайдера: нужны исходные format-bound usage, missing остаётся UNKNOWN.

Общий компактный native prompt можно настроить штатным [параметром агента OpenCode](https://opencode.ai/docs/agents/#prompt). Это замена общих многословных примеров, а не текущего ТЗ, правил владельца или ручного выбора модели.

Модули — чистые функции. Они не вызывают модели, не пишут файлы и не запускают платные probes. Проверка официальных пакетов, original read/result proof, Stop/UNKNOWN, storage, права, безопасная загрузка и следующий обычный consumer остаются обязанностью существующего host. Закрытые адаптеры и продуктовый Source в библиотеку не входят.

## Историческое readonly-наблюдение shell

`readonlyShellObservation(command, {scopeRoots, workdir})` распознаёт ограниченную грамматику обычных чтений: literal `cd`, `sed -n`, `grep`, фильтры и цепочки. Команда не исполняется, корни задаются явно. Применять только после проверки исходного worker/result и точных аргументов. Доверие к исполняемым программам, среде и подписанной идентичности операции остаётся за host; проверка путей лексическая. `true` не разрешает scan/replay, не доказывает завершение потомков тайм-аута и не превращает отсутствие результата в успешное чтение. Интерпретаторы, записи, динамические подстановки и неизвестная грамматика остаются неподтверждёнными.

Для исторического readonly-исхода поддерживаются буквальный guard `cd … || exit 1`, ограниченные `find -maxdepth` с проверкой имён и файловые аргументы `sha256sum`. Классификатор ничего не исполняет и не разрешает повтор, свежий Source или выпуск. Произвольные fallback-команды, действия find и инструкции проверки сумм отклоняются.
