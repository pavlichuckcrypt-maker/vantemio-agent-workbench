# Сопровождение автономной вахты разработки

Назначьте одного сопровождающего инфраструктуры в существующей среде. Он отвечает за общие hooks, контекст, бюджеты запросов, восстановление, skills по необходимости, измерение usage и публичную библиотеку. Продуктовые разработчики самостоятельно ведут свои задачи.

## Изменение и восстановление

1. Сверьте актуальный реестр, полную задачу/Goal/revision, native выбор модели, Stop и оригинальные исходы. Старые заголовки и PID не являются текущим состоянием.
2. Воспроизведите конкретный дефект и исправьте общую причину. Сохраняйте текущий вход, call IDs, завершённые этапы, живые tools и неизвестные эффекты.
3. Проведите соразмерные positive/negative/regression проверки. Quota, авторизация и неподдерживаемая модель требуют исправления конфигурации; техническое восстановление ограничено.
4. Загружайте правку существующим lifecycle на проверенной безопасной границе. Записывайте каждую служебную отмену. Новый вход пользователя или peer делает снимок устаревшим: сначала сверяйте точные ID и текст.
5. Восстановите исходный темп запросов. Продолжайте только квалифицированный незавершённый модельный шаг; не повторяйте инструменты или accepted/unknown доставку. Настоящий Stop сохраняется.
6. Подтвердите завершённую обычную генерацию и следующий штатный tool/caller. Квитанция запуска, принятый resume, helper PASS или статус busy сами по себе не являются приёмкой.

## Контекст и кэш

Сохраняйте стабильный необходимый префикс и привязанные к задаче Source/results с original call, receipt, SHA и диапазоном. Подгружайте skills по необходимости. Архив хранится локально и не переносится целиком в каждый запрос. Корректность Source и продолжение задачи важнее процента кэша. Только provider usage доказывает cache hit; отсутствие счётчика означает unknown.

## Публичные обновления

Проверяйте точный diff, тесты, allowlist/проверку секретов и smoke consumer установленного пакета. Публикуйте переносимый код политик, очищенные примеры и RU/EN документацию. Ключи, история чатов, native IDs, приватные транспорты, пути машин и продуктовый Source остаются вне репозитория. Примеры требуют проверенной интеграции с host: библиотека сама не отправляет модельные запросы и не является готовым сервером OpenCode.
